# seowoo-blog (seowoo.kr) — 콘텐츠 발행 가이드 (색인·AEO)

> 공통 표준: `D:\키워드엔진\docs\콘텐츠 발행 표준.md` (**먼저 읽을 것**)

## 현재 상태 (2026-07-12 실측)

| 항목 | 값 |
|---|---|
| 콘텐츠 | **1건** (`content/posts/`) |
| 렌더링 | MDX + `generateStaticParams` → **완전 SSG** = LLM 크롤러 가독성 최상 |
| robots | `{ userAgent: '*', allow: '/' }` 만 있음 — AI 봇 **명시 없음** |
| JSON-LD | Organization·WebSite·BlogPosting·Person·BreadcrumbList — **FAQPage 없음** |
| llms.txt | **없음** |
| 엔진 편입 | 발행 이력 없음(측정 대상 아님) |

**기술 기반이 4개 자산 중 가장 깨끗한데(순수 SSG) 콘텐츠가 없다.** 투입 대비 효과가 가장 큰 지점이다.

## 지금 해야 할 일 (순서대로)

1. **AI 봇 명시 허용** — `app/robots.ts`에 GPTBot·OAI-SearchBot·ClaudeBot·PerplexityBot·Google-Extended를 명시 추가.
   현재 `*` 허용이라 암묵적으로는 허용되지만, GEO 감사 도구·일부 봇은 명시를 확인한다. authenticart의 `app/robots.ts`를 그대로 참고.
2. **FAQPage 스키마 추가** — `lib/schema.ts`에 FAQPage 생성 함수 추가 + 글 상세에서 출력.
   AI 답변의 상당수가 FAQ 구조에서 나온다. 글마다 FAQ 3~5개를 프론트매터에 넣고 스키마로 노출.
3. **llms.txt 추가** — 비용 낮으니 하되 **효과 기대치는 낮게**(랭킹에 쓰지 않는다고 주요 LLM사가 공언).
4. **콘텐츠 발행 시작** — 공통 표준의 색인 게이트(2,000자+ · 고유 수치 3개+ · 내부링크 2개+ · 추출형식 · FAQ)를 지켜 **적게·두껍게**.
   글 1건 상태에서는 내부링크 2개를 채울 수 없으므로, 초기 3~5편은 서로를 링크하도록 함께 기획할 것.
5. **엔진 편입** — 발행 시작하면:
   ```bash
   node D:\키워드엔진\import_sitemap.js https://seowoo.kr/sitemap.xml seowoo-blog
   ```
   이후 색인 측정·학습·발행 제동이 자동으로 걸린다.

## 하지 말 것

콘텐츠를 빨리 채우겠다고 얇은 글을 대량 발행하는 것. 다른 자산에서 **정확히 그 방식으로 색인률이 80% → 22%로 붕괴**했다.
새 도메인은 특히 초기 인상이 중요하다 — 첫 글들이 두껍고 고유하면 크롤 예산이 늘고, 얇으면 처음부터 크롤 거부를 학습시킨다.
